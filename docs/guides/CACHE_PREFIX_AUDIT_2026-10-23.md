## 08:00–09:00 的零缓存记录

主用渠道 `/api/log/token` 快照中，这一小时有 199 条记录，29 条正常完成、170 条 `client_gone / context canceled`。171 条显示零缓存，其中 170 条就是这些取消请求，输出均为零。取消请求的耗时中位数为 30 秒，97 条在 28–32 秒之间。

此前 DSH 主用流空闲超时为 30 秒、单请求超时为 60 秒，失败默认额外重试 5 次。已部署的 120 秒流空闲、180 秒请求上限和最多额外重试 2 次，针对的是这类过早中断和重复请求。SDK 按语义流事件判断空闲，网络心跳本身不保证刷新计时器。

为核实零缓存字段，使用完全相同的合成文本请求体执行两次完整调用、一次 3 秒后主动取消的调用：

| 调用 | 输入 token | 缓存 token | 输出 token |
| --- | ---: | ---: | ---: |
| 第一次完整返回 | 28,426 | 22,912 | 2 |
| 原样重复 | 28,426 | 28,416 | 35 |
| 原样请求，但主动取消 | 6,377 | 0 | 0 |

NewAPI 主分支 `relay/channel/openai/relay-openai.go` 的无流 usage 路径也会回退到本地输入估算；该源码不是对部署版本逐行匹配的保证。主用渠道报告版本为 v1.0.0-rc.41。参考 [NewAPI 源码](https://github.com/QuantumNous/new-api/blob/main/relay/channel/openai/relay-openai.go)。

## 金额与 token 必须分开解释

本次主用 key 的 980 条渠道记录全部 `quota=0`，所属 `bot` 分组倍率为 0；usage 接口也报告已用额度 0。这只能说明这个 key 的渠道账本没有扣款，不能推广到官方备用、GPT 或渠道运营方的上游费用。

Bridge 显示的是本地价目估算。还发现累计基线按当前快照时间、当前模型整体重新估价的设计：重启或重连后跨越峰谷时段，旧累计量也可能被重估。它不是可靠的真实扣款凭证；本轮未重写账本或将历史费用清零，以免抹掉此前官方渠道的消耗。
