读取 DSH 本机持久化会话事件、模型 usage、重试事件和上下文投影，未向 QQ 发送测试消息。统计在服务运行期间取得，不同快照会随新消息变化。

两个大群会话的单次上下文已约 28 万、36 万 token，分别经过 106/306 和 136/332 个回合/步骤。一个会话的用户提示平均约 4,026 字符；主人身份规则、表情用法等固定段落重复了 129 次。固定前缀不断进入历史，再被后续每一步读取，是可避免的增长。

## 请求错误

排查样本中，`deepseek-primary` 出现 355 次 `TIMEOUT` 重试、18 次 `TRANSPORT` 重试；`local-gpt` 出现 6 次 `SERVER` 重试。失败尝试与重试数量不同：最后一次失败不再产生重试事件。样本包含 42 个因主用超时而失败的回合。

- `TIMEOUT`：主要为 `pi-ai stream idle timeout after 30000ms`，另有 `Request timed out.`。此前主用仅允许 30 秒流空闲和 60 秒请求超时，长上下文或渠道排队会被过早中断；默认又额外重试 5 次。它是客户端错误分类，不是 HTTP 429。
- `TRANSPORT` / `Connection error.`：连接中断或建立失败，日志不足以进一步断言是渠道还是中间网络。
- GPT `SERVER` / HTTP 502：上游明确返回 `Upstream service temporarily unavailable`。
- `PI_AI_ERROR`：新渠道两次返回 web_search/web_fetch 工具的非法 JSON 参数，错误文字包含 `Trae upstream returned invalid JSON arguments`。只能据此确认网关返回格式有误，不能据此确定其真实底层模型。
- `MALFORMED_RESPONSE`：官方渠道有 4 次工具参数 JSON 无效。
- 旧 `UNKNOWN`：早期提示词使用未注册的 `{{cwd}}` 变量，是历史配置错误，不能与本次主用超时混为一谈。

大量失败请求没有可用 usage，不能由本地日志断言它们全部扣费或全部未扣费。失败至少增加了请求数和等待时间。

## 已部署的优化

1. 主用 DeepSeek 的流空闲上限调整为 120 秒、请求上限 180 秒，临时错误最多额外重试 2 次。上限不会让正常请求额外等待；正常返回仍立即处理。GPT 和官方备用设置保持原样。
2. `socialV2.context.deduplicateWakePolicy: true`：固定唤醒规则第一次完整发送，只有同一 DSH 会话已接受且内容逐字相同，才在之后引用已有规则。每次仍携带当前令牌、新消息、状态、记忆、回应节奏和已读水位。规则变化、会话更换、桥接重启、DSH 重连或 compaction 事件都会恢复完整发送。投递失败和并发失效不会错误建立缓存。
3. 修正黑话学习的错误分类：此前任何含“会话”或“session”的异常都会丢弃学习会话映射，连自身生成的“学习会话 turn 未正常完成”也会误触发。现在仅明确的 `session/not-found` / 会话不存在才失效，避免普通请求失败导致会话反复重建。
4. 按用户后续要求关闭黑话学习：通过控制台接口持久化 `slang.enabled=false`、`slang.autoResearch=false`，并清队列、取消全部 16 个已挂载的黑话学习会话的工作。仅操作工作目录为 `state/slang-agent` 的学习会话，保留词库和聊天历史。现成开关在控制台「黑话词库 → 黑话系统参数 → 启用黑话学习」；重新启用时可分别设置学习与自动研究。

同配置离线对照：同样的消息和状态，首次提示 2,776 字符，复用规则后 1,271 字符，减少 1,505 字符（54.2%）。这是新增唤醒提示的字符降幅，不是总 token 或费用降幅。已有历史保留，累计统计不会因为优化下降；实际收益需看后续每轮增量。

未删除历史、未重置聊天会话、未关闭图像或工作工具、未降低模型能力、未缩短输出上限，也未降低聊天唤醒频率。黑话后台学习按用户要求单独关闭。没有强制摘要旧聊天，因为摘要有信息损失风险；若长会话仍持续增长，可另行评估 DSH 原生摘要和保留最近原文的策略。

## 维护与验证

```bash
node ops/configure-token-economy.mjs
qqbridge restart bridge
qqbridge doctor
```

脚本热更新主用 provider 的超时/重试配置，并写入 Bridge 的规则复用开关；不修改其他 provider 的凭据。关闭复用可把该开关设为 `false` 后重启 Bridge。

验证：`node scripts/test-token-economy.mjs`（40 项），`node scripts/test-token-usage.mjs`（账本计数与重放幂等），`node scripts/test-audit-bridge.mjs`（14 项权限、会话与发送回归）。规则复用测试覆盖拒绝投递、失效并发、角色身份变化、重连、上下文压缩和会话更换。

本机明细只保存在被 Git 忽略的 `runtime/token-audit-*.json`，不提交聊天原文和密钥。后续观察重点是每百个成功请求的超时次数、输入缓存比例、每回合步骤数、单次上下文长度；不要只比较累计 token 总量。
